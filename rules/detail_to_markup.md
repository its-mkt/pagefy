# 상세페이지 마크업 변환 규칙 (PSD → HTML)

이 폴더는 **상품 상세페이지 전용**이다. 통짜 이미지(긴 JPG 한 장)로 쓰던 상세페이지를
PSD를 원본으로 삼아 **HTML 마크업**으로 바꾼다. 담당자는 완성된 HTML 코드를 **직접 복사해 각 채널에 등록**한다.
아래 규칙은 변환 중 생기기 쉬운 문제(글자 깨짐·줄바꿈 틀어짐·숨긴 레이어 노출·효과 누락·모바일 깨짐·
붙여넣기 후 깨짐)를 막기 위한 것이다.

---

## 1. 기본 원칙

1. **PSD가 유일한 원본이다.** 텍스트·색상·크기·간격은 PSD 레이어 값에서 읽는다.
   JPG를 보고 눈대중으로 추정하거나 OCR 로 글자를 옮기지 않는다 (JPG는 대조용)
2. **보이는 레이어만 변환한다.** 꺼진(숨김) 레이어는 안 쓰는 레이어다 → 3절 참고
3. **PSD·JPG는 읽기 전용이다.** 변환 중 PSD를 저장·덮어쓰기·레이어 삭제하지 않는다.
   레이어를 켜고 끄며 내보낼 일이 있으면 작업 후 원래 상태로 되돌리고, **저장하지 않고 닫는다**
4. **텍스트는 텍스트로, 그림은 그림으로.** 텍스트 레이어는 실제 HTML 글자로 만들어
   검색·수정·번역이 가능하게 한다. 예외는 4절 표에 정한 경우만
5. **복사 한 번으로 끝나는 코드.** 담당자가 복사 구간만 붙여넣으면 그대로 보여야 한다 (7절)
6. **완료 전 실물 대조.** 브라우저 렌더 화면을 PSD 렌더와 겹쳐 비교한 뒤에만 완료라고 보고한다 (9절)

## 2. 폴더 구조 (이 구조만 쓴다)

```
A_상세페이지/
  detail_to_markup.md           ← 이 파일 (규칙 본문)
  CLAUDE.md                     ← `@detail_to_markup.md` 한 줄 (Claude Code 가 자동으로 읽게 연결)
  아이티켓/                       ← 채널 묶음 (고도몰)
    <제품명>/                     ← 폴더명 = 제품명
      <제품명>.psd                원본 (수정 금지)
      <제품명>.jpg                기존 이미지 (대조용, 수정 금지)
      <제품명>.html               ← 변환 결과
      img/<rev>/                  ← HTML에 쓰는 이미지 (서버 `<채널>/<슬러그>/<rev>/` 와 똑같은 파일·이름, 6-1)
  온코어/                         ← 채널 묶음 (고도몰)
  오픈마켓/                       ← 채널 묶음 (스마트스토어·쿠팡·컴퓨존·11번가·G마켓·롯데온·하이마트)
```

- 제품 폴더 안에는 **psd · jpg · html 세 파일과 img 폴더만** 둔다. img 에는 지금 HTML이 쓰는 rev 폴더 하나만 두고, 레이어 정보·보고서·캡처 등
  작업 중 생기는 파일은 모두 작업용 임시 폴더(scratchpad)에 두고 제품 폴더에 남기지 않는다
- HTML 파일명은 폴더명(=제품명)과 같게 한다 (예: `ZGX Nano AI Station/ZGX Nano AI Station.html`)
- 상위 채널 폴더(아이티켓·온코어·오픈마켓)가 HTML 작성 방식을 정한다 (7절)
- 이미지는 NHN 이미지 호스팅에 올리고 HTML에는 그 주소만 쓴다 (6절)
- HTML이 이미 있으면 덮어쓰기 전에 사용자에게 확인한다

## 3. Photoshop MCP 작업 절차

1. `photoshop_ping` (세션당 1회) → 실패하면 사용자에게 Photoshop 실행을 요청하고 멈춘다
2. `photoshop_open_image` 로 PSD 열기 → `photoshop_get_state` 로 `document.id`·폭·높이·해상도·색상모드 확인.
   이후 모든 호출에 `document_id` 를 고정해서 넘긴다 (다른 탭 오작동 방지)
3. `photoshop_execute_script` 로 **레이어 트리 전체를 재귀 추출**해 임시 폴더에 `layers.json` 으로 저장한다.
   레이어마다 다음 값을 남긴다:
   - 공통: 이름, 경로(그룹 계층), 종류(text / pixel / smartObject / shape / solidFill / gradientFill / adjustment / group),
     visible, opacity, fillOpacity, blendMode, bounds(left/top/right/bottom), 클리핑 마스크 여부, 레이어 마스크 여부
   - 텍스트: 내용(줄바꿈 포함), 폰트 PostScript 이름, 크기(pt→px 환산), 색상, 행간(leading), 자간(tracking),
     정렬, 포인트/단락 텍스트 구분, 글자 범위별 스타일이 섞였는지 여부
   - 레이어 스타일(효과): 드롭섀도·획·그라데이션/색상 오버레이·내부 그림자·외부 광선 등 켜진 효과 목록과 값
4. **사용 레이어 판정** ― 아래 중 하나라도 해당하면 변환 대상에서 뺀다
   - `visible = false` 인 레이어
   - 숨김 그룹 안의 모든 하위 레이어 (자식이 켜져 있어도 부모가 꺼지면 제외)
   - opacity 0% 이거나 bounds 가 캔버스 밖에 완전히 벗어난 레이어
   - 레이어 효과 중 꺼진 효과 (켜진 효과만 반영)
5. 섹션 나누기 ― 최상위 그룹 = 섹션 하나. 그룹 없이 레이어만 있으면 큰 배경 레이어나
   세로 여백 기준으로 섹션을 나누고, 나눈 근거를 완료 보고에 적는다
6. 이미지 내보내기 ― 섹션마다 필요한 레이어만 보이게 한 상태로 해당 영역을 잘라 **임시 폴더에** 내보낸다
   (`photoshop_export_as` 또는 스크립트의 복제 문서 + crop). 작업 후 레이어 표시 상태를 원래대로 복원하고
   PSD는 **저장하지 않고** 닫는다

## 4. 레이어 종류별 변환 규칙

| PSD 레이어 | HTML/CSS 변환 | 이미지로 굽는(bake) 경우 |
|---|---|---|
| **텍스트 레이어** | `h2`·`h3`·`p`·`span` 등 실제 텍스트. 크기·행간·자간·색·정렬을 PSD 값으로 지정 | 뒤틀기(warp)·3D·패턴/그라데이션 채운 장식 글자·이미지 클리핑된 글자·로고 타입 → 이미지로 내보내고 `alt` 에 원문 그대로 |
| **이미지(픽셀·스마트오브젝트)** | `<img>` (사진 JPG, 투명이 필요하면 PNG) | 위에 조정 레이어·클리핑·비표준 혼합모드가 걸려 있으면 **겹친 결과를 합쳐서** 한 장으로 내보낸다 |
| **스타일 레이어 ― 단색 채우기·사각형 셰이프** | `background-color`, 둥근 모서리는 `border-radius`, 획은 `border` | 사각형이 아닌 자유 도형 → PNG |
| **스타일 레이어 ― 그라데이션 채우기** | `linear-gradient` / `radial-gradient` (각도·색 정지점 PSD 값 그대로) | 노이즈·디더가 보이는 복잡한 그라데이션, 또는 오픈마켓용에서 그라데이션이 지워지는 경우 → 이미지 |
| **레이어 효과** | 드롭섀도 → `box-shadow`/`text-shadow`, 획 → `border`, 색상 오버레이 → `color`/`background` | 광선·새틴·베벨·내부 그림자 등 CSS로 같게 안 나오는 효과 → 이미지 |
| **조정 레이어 (곡선·색조 등)** | CSS로 옮기지 않는다 | 항상 아래 이미지와 합쳐서 굽는다 |
| **혼합모드 (표준 외)** | 원칙적으로 사용 안 함 | 결과를 합쳐 굽는다 |

- **환산 기준**: PSD 1px = 디자인 1px. pt 단위 텍스트는 문서 해상도로 px 환산 (72ppi 면 1pt=1px)
- **행간**: leading(px) → `line-height`. 자동 행간이면 PSD 실제 줄 간격을 bounds 로 계산한다
- **자간**: tracking 값 ÷ 1000 = `letter-spacing` em (예: -25 → `-0.025em`)
- **강제 줄바꿈**: 텍스트 내용의 줄바꿈(`\r`)은 `<br>` 로 옮겨 PSD와 같은 위치에서 끊는다
- **한 레이어 안 스타일 섞임**: 글자 범위별로 굵기·색이 다르면 `<strong>`/`<span>` 으로 나눈다
- 이미지로 구운 텍스트는 완료 보고에 목록으로 적는다 (나중에 문구를 고치려면 PSD를 다시 열어야 함)

### 4-1. 텍스트 위치를 PSD와 똑같이 맞추는 법 (첫 변환 ZGX Nano 에서 실측, 2026-11-19)

- **크기·행간 값**: AM 디스크립터의 `impliedFontSize`·`impliedLeading` 이 변형(transform)까지 반영된 실제 px 값이다.
  `textItem.size` 나 transform 배율을 다시 곱하지 않는다
- **기준선**: 점(point) 텍스트의 `textItem.position[1]` = 첫 줄 기준선. 단락(상자) 텍스트는 position 이 상자 위쪽이므로
  첫 기준선 = position + 0.76 × 글자 크기
- **CSS 배치 공식 (Pretendard)**: 줄 상자 위쪽 = 기준선 − (line-height ÷ 2 + 0.35 × 글자 크기)
- **기준선 이동(baselineShift)**: 변형 전 값이므로 × transform yy 해서 위로 올린다
- **줄마다 행간이 다를 때**: 포토샵은 줄바꿈 문자를 뺀 그 줄 글자들의 행간 중 가장 큰 값을 쓴다. 줄을 블록으로 나누고
  블록의 font-size 도 그 줄 크기로 맞춘다 (부모 글자 크기로 기준선이 잡히는 문제 방지)
- **문단 간격**: `paragraphStyleRange` 의 spaceBefore/spaceAfter 를 문단 사이(`\r`)에 더한다. 소프트 줄바꿈(`\u0003`)에는 넣지 않는다
- **스타일 범위**: `textStyleRange` 는 겹치거나 반복될 수 있다 → 앞에서부터 아직 안 쓴 글자만 쓴다 (안 그러면 글자가 두 번 나옴)
- **모두 대문자**: `fontCaps = allCaps` 면 `text-transform:uppercase` (원문 소문자를 그대로 둔다)
- **가운데·오른쪽 정렬의 끝 공백**: 포토샵은 끝 공백까지 넣어 정렬하므로 `&nbsp;` 로 남긴다
- **글자 폭**: 웹 렌더가 포토샵보다 약 1% 넓다 → PSD 렌더와 줄 폭을 재서 텍스트별 letter-spacing 을 보정한다
- **검증 기준**: 텍스트마다 PSD 렌더와 HTML 렌더의 잉크 위치를 비교해 세로 ±3px·가로 ±6px 안이면 통과
- 생성·검증 스크립트: `C:\Users\user\.claude\tools\psd2html\` (build·compare·linecheck·widthadj, 각자 PC 사본)

## 5. 레이아웃 · 폰트 규칙 (깨짐 방지)

1. **흐름(flow) 레이아웃이 기본.** 섹션 안 요소는 위→아래 순서대로 쌓고, 간격은 bounds 차이로 계산한
   `margin`/`padding` 으로 준다. `position: absolute` 는 쓰지 않는다 (오픈마켓 에디터가 지우는 경우가 많고, 글자가 길어지면 겹침)
2. **글자 상자에 고정 높이 금지.** `height` 를 고정하지 않는다
3. **폭**: 최상위 `width:100%; max-width:<PSD 폭>px; margin:0 auto`. 이미지는 `display:block; width:100%; height:auto`.
   고정 px 폭 박스를 만들지 않는다
4. **한국어 줄바꿈**: `word-break: keep-all; overflow-wrap: anywhere;` 를 최상위에 건다
5. **폰트 매핑**: PSD 폰트(PostScript 이름)를 웹폰트로 1:1 매핑한다. 아래 표에 없는 폰트가 나오면
   **임의로 대체하지 말고** 사용자에게 묻고, 정해지면 표에 추가한다

   | PSD 폰트 | 웹폰트 | 불러오는 곳 |
   |---|---|---|
   | Pretendard-Light / Regular / Medium / SemiBold / Bold | Pretendard 300 / 400 / 500 / 600 / 700 | `https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/static/pretendard.min.css` |
   | Paperlogy-1Thin ~ 9Black (앞 숫자 = 굵기 단계). 이름 앞부분이 빠진 `-3Light`·`-5Medium` 처럼 읽혀도 페이퍼로지로 본다 | Paperlogy 100 ~ 900 (숫자 × 100) | `https://cdn.jsdelivr.net/gh/fonts-archive/Paperlogy/Paperlogy.css` (SIL OFL, 웹 사용 가능) |

   **웹폰트로 쓰지 않고 이미지로 굽는 폰트** (2026-11-20 결정): 이 폰트가 쓰인 텍스트 레이어는 이미지로 굽고 `alt` 에 원문을 그대로 넣는다

   | PSD 폰트 | 이유 |
   |---|---|
   | KoreanCNM-* | 웹폰트 미정 → 모양을 지키려고 이미지로 |
   | RixYeoljeongdo* (Rix열정도체) | 웹폰트 미정 → 모양을 지키려고 이미지로 |
   | NotoColorEmoji* (이모지) | 기기마다 이모지 모양이 달라짐 → 이미지로 |

6. 굵기(weight)는 PSD 폰트 스타일 이름(Regular/Medium/Bold…)을 숫자 weight 로 맞춘다
7. `font-family` 에는 항상 대체 폰트를 함께 쓴다 (예: `'Pretendard','Noto Sans KR','Malgun Gothic',sans-serif`).
   오픈마켓은 웹폰트를 못 불러오는 경우가 많으므로 **대체 폰트로 봐도 줄 넘침이 없게** 만든다.
   폰트 모양이 중요한 문구(헤드카피 등)는 이미지로 굽는 것을 우선 검토한다
8. 라이선스가 웹 사용을 허용하지 않는 폰트는 웹폰트로 쓰지 않는다 → 해당 텍스트를 이미지로 굽는다

## 6. 이미지 호스팅 (NHN 이미지 호스팅 · FTP)

HTML 안 이미지는 모두 **NHN 이미지 호스팅에 올린 절대 URL(https)** 로 쓴다. 상대경로·base64 금지.

- **접속 정보는 이 폴더에 적지 않는다.** (공유 폴더라 여러 사람이 본다)
  FTP 호스트·아이디·비밀번호·공개 URL 주소는 각자 PC의 `C:\Users\user\.claude\secrets\nhn-image-ftp.env` 에 둔다
  ```
  FTP_HOST=
  FTP_USER=
  FTP_PASS=
  FTP_ROOT=          # 상세페이지 이미지를 둘 FTP 폴더 (예: /detail)
  PUBLIC_BASE=       # FTP_ROOT 가 웹에서 보이는 주소 (예: https://…/detail)
  ```
  파일이 없거나 값이 비어 있으면 업로드하지 말고 사용자에게 채워 달라고 요청한다.
  접속 정보를 채팅·HTML·로그·커밋에 출력하지 않는다
- **서버 정보** (비밀 아님): 고도 웹호스팅 `itketweb.hgodo.com`, 포트 21, 암호화 없는 일반 FTP.
  FTP 경로 `/X` = 웹 주소 `https://itketweb.hgodo.com/X` (2026-11-19 확인).
  상세페이지 이미지는 전용 폴더 **`/data/detail`** 에만 올린다 (`/data/img`·`/data/editor`·`/goods` 등 기존 폴더는 건드리지 않는다)
- 스크립트에서 접속 정보를 쓸 때는 env 파일을 읽어 변수로 넘기고, 명령어 출력에 비밀번호가 찍히지 않게 한다
- **용량**: 사진 JPG 품질 80~85, 한 장 1MB 이하 목표. 세로가 3,000px 를 넘는 이미지는 섹션 경계에서 나눈다
- 업로드 후 모든 이미지 URL 을 실제로 열어 200 응답과 이미지 표시를 확인한다 (9절)

### 6-1. 이미지 경로 규칙 (서버 폴더 구조)

경로는 사람이 고르지 않고 **아래 규칙으로만 만든다.** 경로만 보고 어느 채널·제품·버전·섹션·용도의 이미지인지 알 수 있어야 한다.

```
/data/detail/<채널>/<제품슬러그>/<rev>/<파일명>
 └ 웹 주소: https://itketweb.hgodo.com/data/detail/<채널>/<제품슬러그>/<rev>/<파일명>

예) /data/detail/itket/zgx-nano-ai-station/20261120/s05_img1-connectx-stack.jpg
```

| 자리 | 규칙 | 예 |
|---|---|---|
| **채널** | 상위 폴더로 정한다: 아이티켓 `itket` · 온코어 `oncore` · 오픈마켓 `openmarket` | `itket` |
| **제품슬러그** | 제품 폴더명을 영문 소문자로, 공백·특수문자는 `-` 하나로, 앞뒤 `-` 제거. 한 번 정하면 **바꾸지 않는다** | `ZGX Nano AI Station` → `zgx-nano-ai-station` |
| **rev** | 이미지 묶음을 올린 날짜 `YYYYMMDD`. 같은 날 다시 올리면 `YYYYMMDD-2`, `-3` … | `20261120` |
| **파일명** | `s<섹션 2자리>_<종류><순번>[-<내용>].<확장자>` (아래 종류 표). 영문 소문자·숫자·`_`·`-` 만 | `s02_img2-gpu-cpu.jpg` |

**파일 종류** (순번은 섹션 안에서 종류별로 위→아래 1부터)

| 종류 | 무엇 | 파일명 | 내용 이름 |
|---|---|---|---|
| `bg` | 글자 뒤에 까는 배경 띠 (CSS 배경) | `s01_bg1.jpg` | 붙이지 않음 |
| `bg…-m` | 모바일 셀 배경 (그 배경 띠를 셀 크기로 자른 것, 좁은 화면에서만 받음 ― 7-5) | `s06_bg3-m1.jpg` | 붙이지 않음 (셀 번호만) |
| `img` | 정보가 있는 사진 (`<img alt>`, 8-2 7항) | `s03_img1-local-ai.jpg` | 필수 ― 무엇인지 영문 |
| `txt` | 이미지로 구운 글자 (4절 예외) | `s00_txt1-hero-title.png` | 필수 |
| `ico` | 아이콘·배지 단독 이미지 | `s09_ico1-mil-std.png` | 필수 |
| `gif` | 움직이는 이미지 | `s04_gif1-dgx-dashboard.gif` | 필수 |

- **rev 폴더 하나 = HTML 하나.** HTML은 한 rev 폴더의 이미지만 쓴다. 이미지가 한 장이라도 바뀌면 **새 rev 폴더에 전체를 다시 올리고**
  HTML 주소를 새 rev 로 바꾼다 (바뀌지 않은 이미지도 같이 올린다)
- **이미 올린 rev 폴더는 고치지 않는다.** 파일 추가·덮어쓰기·이름 변경 금지 → 이미 등록된 채널 페이지와 캐시가 깨지지 않게
- **로컬과 서버는 같은 모양**: 제품 폴더 `img/<rev>/` = 서버 `<채널>/<제품슬러그>/<rev>/`. 로컬 img 에는 지금 HTML이 쓰는 rev 하나만 둔다
- 지난 rev 폴더 삭제는 사용자 지시가 있을 때만 (서버). 담당자가 새 HTML로 다시 등록한 것을 확인한 뒤에 정리한다.
  지우기 전에 서버 파일을 내려받아 각자 PC `C:\Users\user\.claude\backups\detail-hosting\<채널>\<슬러그>\<rev>\` 에 백업하고
  (공유 폴더에는 두지 않는다), 지금 HTML이 그 파일을 쓰지 않는지 확인한 뒤 지운다
- 제품 폴더명이 한글이라 슬러그를 만들 수 없으면 PSD의 영문 모델명으로 만들고, 그것도 없으면 사용자에게 묻는다.
  정한 슬러그는 HTML 이미지 주소에 남으므로 다음 작업 때 그 HTML에서 읽어 그대로 쓴다
- **도구**: 생성 `build.js` 가 이 규칙대로 파일명·주소를 만들고, 업로드는 `upload.js <제품폴더> <채널> <슬러그> <rev>` 로 한다
  (`C:\Users\user\.claude\tools\psd2html\`). upload.js 는 파일명 규칙 위반·이미 있는 rev 폴더면 멈추고, 올린 뒤 모든 주소의 200·용량을 확인한다

## 7. HTML 작성 방식 (담당자 복사·붙여넣기용)

### 7-1. 파일 모양 (공통)

`<제품명>.html` 은 브라우저로 열어 미리 볼 수 있는 완전한 문서로 만들되, 담당자가 복사할 구간을 주석으로 표시한다.

```html
<!doctype html>
<html lang="ko"><head><meta charset="utf-8"><meta name="viewport" content="width=device-width,initial-scale=1">
<title>제품명 상세페이지</title></head>
<body style="margin:0">
<!-- ▼▼▼ 여기부터 복사 (제품명 / 채널: 고도몰|오픈마켓 / 작성일 YYYY-MM-DD) ▼▼▼ -->
<div class="dp dp-zgx" style="...">
  ...
</div>
<!-- ▲▲▲ 여기까지 복사 ▲▲▲ -->
</body></html>
```

- 복사 구간 밖에는 미리보기용 최소 코드만 둔다. 복사 구간 **안에** 필요한 것(스타일·폰트)이 전부 들어 있어야 한다
- 공통 금지: `<script>`·`<iframe>`·`<form>`·외부 단축 URL(naver.me 등)·`position:absolute`
- 모든 `<img>` 에 `alt`, `width`·`height` 속성(원본 px)을 넣는다
- 들여쓰기는 2칸, 섹션마다 `<!-- s01 메인 비주얼 -->` 처럼 주석을 달아 담당자가 위치를 찾기 쉽게 한다

### 7-2. 아이티켓 · 온코어 폴더 → 고도몰용

- 복사 구간 맨 앞에 `<style>` 하나를 두고, 모든 선택자를 고유 접두사로 시작한다 (`.dp-zgx …`).
  태그 선택자만 단독으로 쓰지 않는다 (`h2 {}` 금지, `.dp-zgx h2 {}` 허용) → 고도몰 스킨 CSS와 충돌 방지
- 웹폰트는 `<style>` 안 `@import` 로 불러온다
- 상세 영역이 디자인 폭보다 좁으면 전체가 비율대로 줄어들게 한다 (그대로 두면 작은 글자가 읽히지 않으므로 **7-5 모바일 규칙을 반드시 함께 적용**). 기준은 **화면 폭(vw)이 아니라 상세 영역 폭(cqw)** 이다
  (고도몰 상세 영역이 화면보다 좁거나 스크롤바가 있으면 vw 기준은 배경과 글자가 어긋남 ― 첫 변환에서 확인)
  ```css
  .dp-zgx { --u: min(1px, calc(100vw / 860)); container-type: inline-size; } /* vw 는 구형 브라우저용 대체값 */
  @supports (width:1cqw) { .dp-zgx > * { --u: calc(100cqw / 860); } }        /* 860 = PSD 폭 */
  .dp-zgx h2 { font-size: calc(40 * var(--u)); }                             /* 40 = PSD px 값 */
  ```
- 스킨 CSS 방어: 최상위 `.dp-…` 에 letter-spacing·text-transform·font-weight·font-size·padding 을 직접 고정하고,
  `.dp-… *` 에 `margin:0;padding:0;font:inherit;color:inherit;letter-spacing:inherit` 를 건다
  (최상위 div 자체가 스킨의 `div{…}` 를 받으면 안쪽 전체로 번진다 ― 첫 변환에서 확인)
- 구성(첫 변환 기준): 섹션마다 **글자를 뺀 PSD 합성 이미지를 배경**(`background-size:100% auto`, `min-height`)으로 깔고,
  글자는 흐름 배치 행(flex) 안에 PSD 기준선 위치로 놓는다. 섹션 경계는 글자가 걸치지 않는 세로 위치에서 자른다.
  글자와 겹치지 않는 제품 사진은 배경에 넣지 말고 `<img>` 로 둔다 (8-2 7항)
- 고도몰 상세설명 에디터가 `<style>` 을 지우는 것으로 확인되면 7-3(인라인) 방식으로 바꾸고 이 절에 적는다
  (2026-11-20 확인: 지우지 않음 → 아래 7-2-1 의 1항)

#### 7-2-1. 고도몰 마크업 기준 (실측 근거, 2026-11-20)

**확인한 사실** (실제 상품 페이지·스킨 CSS·ZGX 실제 등록본에서 확인. 고도몰 공식 FAQ 에는 "에디터 HTML 모드로 태그·스타일 사용 가능"까지만 있음)

| 항목 | 아이티켓 (itket.com) | 온코어 (on-core.co.kr) |
|---|---|---|
| 상세 영역 | `.item_goods_sec .detail_explain_box .txt-manual` | `.oc-gv-desc` |
| 스킨 | 반응형 하나 (`designbook_air_RES`, 휴대폰도 같은 HTML) | 반응형 (휴대폰도 같은 상세 영역) |
| 상세 영역 폭 | PC 860px / 360px 폰 → 323px | PC 860px / 360px 폰 → 332px |
| 페이지 제목 구조 | 상품명 `<h1>`, 탭 제목 `<h3>`(상세정보·배송안내…) | 상품명 `<h1>` |
| 상세 영역에 거는 스킨 CSS | `.item_goods_sec h3{display:none}`, `.item_goods_sec .detail_explain_box h3{display:none}`, 모바일 `.detail_explain_box .txt-manual img{width:100%;display:block}` | `.oc-gv-desc{text-align:center}`, `.oc-gv-desc p{color:진회색}`, `.oc-gv-desc img{display:block;max-width:100%;height:auto;margin:0 auto}` |

- 에디터(HTML 모드)로 저장해도 `<style>`·class·`<section>`·`aria-*`·`role`·`loading`·`fetchpriority`·인라인 `calc()/var()/min()` 이 **그대로 남는다**
  (ZGX 등록본과 원본 비교 ― 담당자가 손으로 고친 곳 외에는 같음)
- 담당자가 등록 전에 손으로 고친 것: ① `<h3>`·`<h4>` → `<p role="heading" aria-level>` ② 오탈자 2곳 ③ 음수 `padding-top` → 0
  → ①③은 아래 규칙으로 빌드가 처음부터 그렇게 만든다. ②는 PSD 가 원본이므로 완료 보고 "오탈자"에 적어 디자이너가 PSD 를 고치게 한다

**고도몰 복사 구간 규칙**

1. **실제 제목 태그는 `<h2>` 만 쓴다.**
   - `<h1>` 금지 (스킨의 상품명이 h1)
   - `<h3>`~`<h6>` 금지 → 소제목은 `<p role="heading" aria-level="3">`, 그 아래는 `aria-level="4"`
     (아이티켓 스킨이 상세 영역의 h3 를 모두 숨김 ― ZGX 소제목 6개가 화면에서 사라지는 것 확인.
     온코어는 숨기지 않지만 같은 규칙으로 통일한다)
   - 8-2 의 "소제목 h3" 는 고도몰 채널에서는 이 방식으로 읽는다
2. **스킨보다 강한 선택자로 방어한다** (스킨 CSS 는 `.상세영역 p` 처럼 클래스+태그 = 특이도 0,1,1)
   - 초기화는 `.dp-x.dp-x *{…}` (0,2,0), 글자 태그는 `.dp-x.dp-x p, .dp-x.dp-x h2{color:inherit;font-size:inherit;font-weight:inherit}` (0,2,1)
   - `.dp-x *` (0,1,0) 만으로는 진다 → 온코어에서 기본색 글자가 진회색이 되어 검은 배경에서 안 보이는 것 확인
   - 고칠 때는 `!important` 대신 클래스를 겹쳐 특이도를 올린다 (모바일 `@container` 규칙의 `!important` 는 인라인 값을 덮기 위한 것만 허용)
3. **최상위 `.dp-x` 에 `text-align:left` 를 고정한다** (온코어 상세 영역이 가운데 정렬)
4. **`<img>` 는 폭 100% 띠로만 쓴다.** 스킨이 상세 영역 img 에 `width:100%`(아이티켓 모바일)·`max-width:100%;margin:0 auto`(온코어)를
   걸기 때문에 작은 아이콘·배지를 `<img>` 로 두면 늘어나거나 가운데로 간다 → 작은 그림은 배경(셀 배경 포함)으로 둔다
5. **음수 `padding` 금지** (무효 CSS 라 무시됨). 위로 당겨야 하면 첫 줄 `margin-top` 음수로 (빌드가 자동 처리)
6. 모바일 기준 폭은 **화면 폭이 아니라 실제 상세 영역 폭**이다: 360px 폰에서 323~332px → 최소 글자 계산은 280px 영역 기준 (7-5)
7. 7-1 공통 금지(`<script>`·`<iframe>`·`<form>`·`position:absolute`·단축 URL)는 그대로
8. **새 스킨·스킨 개편 후 점검**: 실제 상품 페이지를 브라우저로 열고 상세 영역 안을 복사 구간으로 바꿔 넣어(내 브라우저에서만, 쇼핑몰 변경 없음)
   PC(1400px)·휴대폰(360·320px, 모바일 UA)에서 측정한다 → 숨겨진 글자 0, 기본색이 바뀐 글자 0, 12px 미만 0, 가로 스크롤 없음.
   새 스킨 CSS 에서 상세 영역 선택자(`.txt-manual`·`.oc-gv-desc` 등)가 들어간 규칙을 찾아 위 표를 갱신한다
9. **등록본 대조**: 담당자 등록 후 상품 페이지 소스에서 `.dp-x` 블록을 뽑아 원본 HTML 과 비교한다. 다르면 누가 왜 고쳤는지 확인하고 규칙에 반영한다

### 7-3. 오픈마켓 폴더 → 오픈마켓 공용 (인라인 전용)

HTML 하나를 7개 채널(스마트스토어·쿠팡·컴퓨존·11번가·G마켓·롯데온·하이마트)에 같이 쓴다.

- 어느 채널이 공용 HTML을 못 받는 것으로 확인되면, 그 채널용 처리 방법을 사용자와 정해 이 표에 추가한다

### 7-5. 모바일 (필수 ― 사용자 지시 2026-11-20)

쇼핑몰 방문 대부분이 휴대폰이다. **모바일에서 읽히지 않으면 완성이 아니다.**
비율대로 줄이기만 하면 860px PSD 의 20px 글자가 360px 화면에서 8px 이 된다
(ZGX Nano 첫 변환: 360px 에서 글자 50% 가 12px 미만 → Lighthouse "읽기 쉬운 글자 크기" 실패, 모바일 SEO 감점).

**목표**: 360px 화면에서 **모든 글자 12px 이상**, 가로 스크롤 없음, PC(PSD 폭)는 PSD 그대로.

1. **작은 글자 최소 크기 (자동)**: 셀 밖 글자 중 PSD 크기가 `12 × 860 / 360 ≈ 28.7px` 미만인 것은
   `font-size:max(12px, calc(N * var(--u)))` 로 둔다. 넓은 화면에서는 원래 값이 더 커서 PC는 변하지 않는다.
   **기준은 화면이 아니라 실제 상세 영역 폭**이다 ― 360px 폰에서 아이티켓 323px·온코어 332px (7-2-1).
   그래서 "작은 글자" 기준은 280px 영역에서 12px 미만이 되는 `12 × 860 / 280 ≈ 36.9px` 미만이다 (빌드 `MIN_AREA`)
   - 상자 폭도 같은 비율로 늘리고, 정렬 기준점(왼쪽·가운데·오른쪽)이 PSD 위치에 남도록 왼쪽 여백에서 늘어난 만큼 빼고,
     같은 행 다음 상자 여백에서도 빼 준다 (가운데 정렬 제목이 한쪽으로 밀리는 것 방지)
   - 한 줄짜리는 줄 높이를 그대로 둔다(뒤 행이 밀려 배경과 어긋나지 않게). 여러 줄이면 줄 높이도 같은 비율로 최소값
2. **모바일 셀 (카드·표·도식)**: 그래픽 위 작은 글자가 촘촘해서 1항만으로는 넘치는 영역
   (카드 여러 장, 2단 목록, 구성도, 사진 위 긴 문단)은 **셀**로 나눈다.
   - PC: 셀은 PSD 위치 그대로 (영역 배경 한 장 + 셀 안 글자). 모바일 작업 전과 픽셀 비교 1px 이내
   - 좁은 화면(상세 영역 폭 700px 미만, `@container`): 셀이 1~2단으로 재배치되고, 셀마다 자기 폭 기준으로
     글자·배경이 함께 커진다 (셀 안 `--u = 100cqw / 셀폭`). 셀은 PSD 크기보다 크게 키우지 않는다
   - **단 수는 자동**: 셀 안 가장 작은 글자가 360px 화면(여백 빼고 328px)에서 12px 이상이 되는 가장 많은 단 (셀 수의 약수)
   - 셀 배경: 기본은 PSD 배경을 셀 크기로 잘라 쓴다(`s06_bg3-m1.jpg`, 6-1). 카드 테두리가 두 셀에 걸치는 등
     자르면 어색하면 모바일 상자 CSS(배경색·테두리·둥근 모서리, PSD 색에서 고름)로 그린다
   - 방식 `stack`: 영역 배경을 감추고(영역 왼쪽 가장자리 평균색으로 채움) 셀만 쌓는다 ― 카드·목록·구성도
   - 방식 `below`: 영역 배경(사진 등)은 그대로 두고 셀 글자만 그 아래 상자로 옮긴다 ― 사진 위 긴 문단
   - 셀 경계에 걸친 글자, `stack` 영역 안 셀 밖 글자는 빌드가 오류로 멈춘다 → 셀 좌표를 고친다
   - 셀 좌표는 `notext.png` 를 잘라 보며 카드 외곽선 기준으로 정하고 build.js 의 `REGIONS` 에 적는다
3. **같은 글자를 두 벌 만들지 않는다**: PC용·모바일용 글자를 따로 넣고 번갈아 숨기면 숨긴 글자(8-2)가 된다.
   글자는 한 벌, 배치만 CSS 로 바꾼다
4. **오래된 브라우저**: `@container` 를 모르면 PC 배치를 비율 축소로 보여 준다(깨지지 않음)
5. **PSD 단계 제안**: 본문을 PSD 에서 28px 이상으로 만들면 셀 없이도 모바일 12px 이 된다.
   작은 글자가 많은 PSD 는 완료 보고 "검색 최적화 제안"에 적는다 (PSD 는 고치지 않는다)
6. 고도몰 **모바일 상세설명**: 상품 등록의 "PC 상세설명과 동일" 사용을 기본으로 본다. 모바일 스킨에서 `<style>`·`@container`
   가 살아 있는지는 담당자 첫 등록 후 휴대폰으로 확인 → 그 전까지 "미검증"

## 8. 검색 최적화 (SEO · GEO · AEO)

통짜 이미지를 마크업으로 바꾸는 가장 큰 이유가 이것이다. 목표는 두 가지다.
- **SEO**: 검색엔진(구글·네이버)이 상세페이지 내용을 글자로 읽고 색인한다
- **GEO·AEO**: AI 답변(ChatGPT·Perplexity·구글 AI 개요·네이버 AI 브리핑 등)이 이 페이지에서 사실을 뽑아 **정확하게 인용**한다

원리는 하나다: **읽을 수 있는 글자 + 의미가 드러나는 구조 + 정확한 사실.** 이미지 속 글자는 검색·AI가 거의 읽지 못한다.

### 8-1. 복사 구간이 할 수 있는 것과 없는 것

- 복사 구간은 쇼핑몰 페이지 **본문 일부**로 들어간다. `<title>`·meta description·canonical·og 태그·구조화 데이터(JSON-LD)는
  복사 구간으로 넣을 수 없다 → 고도몰 상품 설정·스킨, 오픈마켓 상품 정보 칸(상품명·속성·태그)에서 처리한다
- **JSON-LD `Product` 는 상세 HTML에 넣지 않는다.** `<script>` 금지(7-1)이고, 고도몰 스킨이 이미 내보내면 중복·충돌한다.
  필요하면 고도몰 스킨 작업으로 따로 진행한다
- 오픈마켓 내부 검색은 상품명·카테고리·속성값 위주라 상세 HTML이 순위에 주는 영향은 확인되지 않았다.
  그래도 아래 규칙은 똑같이 지킨다 (외부 검색·AI 수집·접근성에 쓰임)

### 8-2. 마크업 단계 필수 (문구를 바꾸지 않고 할 수 있는 것)

1. **제목 구조**
   - 복사 구간에 `<h1>` 을 쓰지 않는다. 상품명 `<h1>` 은 쇼핑몰 페이지에 이미 있어서 두 개가 된다
   - 섹션 대제목 `<h2>`, 그 아래 소제목 `<h3>`, 설명은 `<p>`. 글자 크기가 아니라 **의미**로 고르고, 단계를 건너뛰지 않는다 (h2 다음 h4 금지)
   - **고도몰 채널은 h3·h4 대신 `<p role="heading" aria-level="3|4">`** (7-2-1 1항 ― 스킨이 상세 영역 h3 를 숨김)
   - 영문 장식 문구(예: "Key Highlights")와 실제 주제 문구가 함께 있으면, **주제가 드러나는 쪽을 `<h2>`** 로 하고 장식 문구는 `<p>` 로 둔다
   - 크기는 고도몰은 접두사 class, 오픈마켓은 인라인 font-size 로 따로 정한다 (태그 기본 크기에 기대지 않는다)
2. **섹션 묶음**: 고도몰은 섹션마다 `<section aria-labelledby="dp-<제품>-s01">` 로 묶고 그 섹션 `<h2 id>` 와 연결한다.
   id·class 는 전부 고유 접두사로 시작한다. 오픈마켓은 `<section>` 이 지워질 수 있으므로 `<div>` 로 해도 된다
3. **글자는 글자로**: 정보가 있는 문구는 HTML 글자로 둔다 (4절 예외만 이미지). 이미지로 구웠으면 `alt` 에 원문을 **빠짐없이** 적는다
4. **핵심 사실은 반드시 글자**: 모델명·CPU·GPU·메모리·저장장치·포트·크기·무게·OS·보증 같은 수치는 이미지나 아이콘만으로 표현하지 않는다.
   숫자와 단위는 붙여 쓴 글자로 둔다 (`128GB`, `1.2kg`)
5. **스펙·비교는 표·목록 구조로**: PSD에서 표 모양인 스펙은 `<table>`(머리칸 `<th scope="row|col">`),
   "항목: 값" 나열은 `<dl><dt><dd>`, 나열 항목은 `<ul><li>` 로 만든다. AI가 가장 정확히 뽑아 가는 형태다
6. **이미지 `alt`**
   - 정보가 있는 이미지: 정식 모델명 + 보이는 것을 구체적으로 (예: `HP ZGX Nano G1n AI Station 후면 포트 구성`)
   - 장식 이미지(배경 무늬·구분선): `alt=""`
   - 키워드 나열·같은 문구 반복 금지
7. **검색에 보여야 할 그림은 `<img>`**: CSS 배경 이미지는 검색·이미지 검색이 읽지 않는다.
   글자와 겹치지 않는 제품 사진 영역은 배경 띠에서 떼어 `<img>` 띠로 넣고, 배경 이미지는 글자 뒤 판·장식에만 쓴다
8. **이름 표기 통일**: 제품 정식 모델명은 PSD 표기 그대로 쓰고, `alt`·`aria-label` 에서도 같은 이름을 쓴다 (줄임말·다른 표기를 섞지 않는다)
9. **숨긴 글자 금지**: 화면에 안 보이는 글자(배경색과 같은 글자색·`font-size:0`·`display:none`·화면 밖 배치)나 `aria-label`·`alt` 에
   키워드를 넣지 않는다. 검색엔진 스팸 정책(숨김 텍스트) 위반이라 오히려 노출에서 빠질 수 있다
10. **읽기 순서**: CSS를 끈 상태에서도 내용이 위→아래 의미 순서대로 읽히게 한다 (흐름 레이아웃 ― 5절 1항)
11. **속도 (Core Web Vitals)**
    - 첫 화면 이미지 `loading="eager" fetchpriority="high"`, 나머지 `<img>` 는 `loading="lazy" decoding="async"`
    - 모든 `<img>` 에 `width`·`height` 속성 (화면 밀림 방지 ― 7-1)
    - CSS 배경 이미지는 지연 로딩이 안 되므로 6절 용량 기준을 더 엄격히 지킨다 (섹션당 200KB 안팎 목표)
    - 웹폰트는 `font-display:swap` 이 들어 있는 CSS만 쓴다 (글자가 늦게 뜨는 것 방지)
12. **이미지 파일명**: 6-1 규칙의 내용 이름을 무엇인지 드러나는 영문으로 쓴다 (`s12_img1-rear-ports.jpg` 좋음, `s12_img1-photo.jpg` 나쁨)

### 8-3. GEO · AEO ― AI 답변에 인용되게

AI는 페이지에서 **질문에 바로 답하는 짧고 사실적인 글자 덩어리**를 골라 인용한다.

1. **섹션 하나 = 주제 하나**: `<h2>` 가 그 섹션이 답하는 주제를 나타내게 고르고(8-2 1항), 설명 `<p>` 는 그 바로 아래 둔다
2. **사실을 문장 안에 완결되게**: 한 문단만 떼어 읽어도 무슨 제품의 무엇인지 알 수 있어야 인용된다.
   표·목록은 머리칸(항목명)을 꼭 글자로 둔다 (값만 있는 표 금지)
3. **PSD에 있는 FAQ·요약·스펙 표는 구조로 살린다**: FAQ는 질문 `<h3>` + 답 `<p>` (또는 `<dl>`), 펼친 상태로 둔다
   (`<details>` 처럼 접는 태그는 오픈마켓에서 지워지고 내용이 숨겨진다)
4. **PSD 기획 단계 제안 (마크업에서 지어 넣지 않는다)**: 문구는 PSD에서만 오므로(10절), 아래가 PSD에 없으면
   완료 보고의 "검색 최적화 제안"에 적어 디자인·기획 담당에게 넘긴다
   - **첫 화면 요약 2~3문장**: 무엇인지 · 누구에게 · 핵심 수치 (예: "○○는 ○○용 ○○. ○○ 탑재, ○○ 지원")
   - **전체 스펙 표**: 모델명·주요 부품·크기·무게·OS·구성품·보증
   - **FAQ 3~6개**: 질문은 고객이 실제로 검색하는 문장 그대로, 답은 첫 문장에 결론(40~60자) + 근거
   - **호환·구성품·AS/보증 안내**
   - **수치·비교 주장의 근거**: "최대 ○배" 같은 주장에는 측정 조건·출처
5. **최신 정보 유지**: 복사 구간 시작 주석에 작성일을 남기고(7-1), 스펙·가격 정책이 바뀌면 PSD와 HTML을 함께 고친다.
   AI·검색은 페이지끼리 내용이 다르면 신뢰를 낮춘다 (같은 제품의 채널별 HTML 수치가 서로 같아야 한다)

### 8-4. 검색 최적화 점검 (9절 검증에 포함)

- `<h1>` 0개, `<h2>`→`<h3>` 단계 건너뜀 없음, 섹션마다 `<h2>` 하나 (고도몰은 `<h3>`~`<h6>` 0개, 소제목은 `role="heading"`)
- 핵심 사실(8-2 4항)이 전부 HTML 글자인지 · 구운 텍스트는 목록과 `alt` 원문 확인
- 모든 `<img>` 에 `alt` (장식만 빈 값), `width`·`height`, 첫 화면 외 `loading="lazy"`
- 숨긴 글자·키워드 나열 없음
- CSS를 끈 화면(또는 텍스트만 추출)에서 내용이 의미 순서대로 읽히는지
- 가능하면 미리보기 HTML로 Lighthouse SEO·접근성 점수를 재서 완료 보고에 적는다

## 9. 검증 (완료 보고 전 필수)

캡처 등 검증 파일은 모두 임시 폴더에 둔다.

1. **PSD 기준 렌더**: 보이는 레이어만 켠 상태의 PSD 전체를 PNG로 내보낸다
2. **브라우저 렌더**: `<제품명>.html` 을 PSD 폭으로 열어 전체 화면 캡처. 스크롤바를 숨겨 콘텐츠 폭이 정확히 PSD 폭이 되게 하고,
   `loading="lazy"` 이미지는 캡처 전에 모두 불러와 디코딩한다 (안 그러면 사진 자리가 검게 찍힘 ― 2026-11-20 확인)
3. **겹쳐 비교**: 섹션별로 두 이미지를 나란히/겹쳐 보고 위치·크기·줄바꿈·색 차이를 확인한다.
   섹션 높이 차이가 디자인 폭 대비 2% 를 넘거나 줄바꿈 위치가 다르면 고친다
4. **텍스트 누락 검사**: 사용(visible) 텍스트 레이어 내용이 HTML 텍스트 또는 구운 이미지 `alt` 에
   빠짐없이 들어 있는지 대조한다. 숨김 레이어 내용이 HTML에 들어가 있으면 오류
5. **모바일 확인 (필수, 7-5)**: 360·390·430·768px 폭에서 다음을 **측정**하고 섹션별 캡처를 눈으로 본다
   - 가로 스크롤 없음 (`scrollWidth` = 화면 폭)
   - 12px 미만 글자 0% (숫자 라벨 포함)
   - 글자 상자 넘침(`scrollWidth > clientWidth`) 0개, 같은 행 이웃 글자끼리 겹침 0개
   - 셀 영역이 1~2단으로 재배치되고 셀 배경(카드·아이콘)이 제자리에 보이는지
   - PC(PSD 폭) 렌더가 모바일 작업 전과 같은지 (픽셀 비교, 1px 이내)

## 10. 하지 말 것

- PSD·JPG 저장·덮어쓰기·레이어 삭제·병합 후 저장
- 제품 폴더에 psd·jpg·html·img 외의 파일 남기기
- 숨김 레이어나 숨김 그룹 내용을 HTML에 넣기
- JPG를 잘라 통째로 붙이기 (텍스트 영역을 이미지로 쓰는 것은 4절 예외만)
- PSD에 없는 문구·수치를 추가하거나 문구를 고쳐 쓰기 (오탈자를 발견하면 고치지 말고 완료 보고에 적는다. SEO용 문구도 마찬가지 → 8-3 4항처럼 제안만)
  - **예외 ― 승인된 오탈자 교정**: 사용자가 승인한 오탈자만 HTML 에서 고칠 수 있다. build.js `CORRECTIONS` 에
    [레이어 경로, 틀린 문구, 고친 문구, 승인자·날짜] 로 적고(빌드가 적용 여부를 검사), 완료 보고에 목록을 남긴다.
    PSD 는 고치지 않으며 디자이너에게 PSD 수정을 요청한다 (PSD 가 고쳐지면 그 항목은 지운다).
    예: ZGX `PERFOMANCE→PERFORMANCE`, `컴펙트→컴팩트` (2026-11-20 승인, 담당자가 등록본에서 먼저 고친 것과 같음)
- 폰트를 묻지 않고 다른 폰트로 대체하기
- FTP 접속 정보를 이 폴더·HTML·채팅에 적기, 서버 이미지 덮어쓰기·삭제
- 복사 구간에 `<h1>`·JSON-LD·meta 태그 넣기, 숨긴 글자나 `alt`·`aria-label` 로 키워드 채우기 (8절)
- 모바일을 "비율대로 줄어드니 괜찮다"로 넘기기 ― 360px 에서 12px 미만 글자가 남으면 미완성 (7-5)
- 모바일용 글자를 따로 한 벌 더 만들어 PC/모바일에서 번갈아 숨기기 (같은 글자 중복 = 숨긴 글자, 8-2)
